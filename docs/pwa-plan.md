# План: PWA (установка на десктоп/телефон, работа офлайн)

Задача: из браузера приложение устанавливается как иконка на десктоп/домашний экран,
открывается в собственном окне (standalone) и работает без интернета в части UI,
сохраняя все настройки (`localStorage`: лайки, свои станции, тема).

## Оценка сложности

**Ниже среднего: минимальный рабочий вариант — 2–4 часа, доведённый до полировки — до дня.**

Приложение уже архитектурно готово к PWA:

- serverless: весь UI — статика (бандлы + HTML), данные станций зашиты в бандл на этапе сборки (`stations.json` импортируется);
- лайки/свои станции/тема уже в `localStorage`, а merge-логика (`clientStateMergeMutate` в `src/hooks/useStations.ts`) сшивает их со списком станций при каждом старте — для офлайна ничего менять не нужно;
- аудио-потоки офлайн не играют — это ожидаемо, плеер уже умеет показывать error-состояние.

Важно: плагины вида `next-pwa` / `@ducanh2912/next-pwa` — это webpack-плагины, а Next.js 16 собирает
билд через **Turbopack** — совместимость не гарантирована. Поэтому ниже — рукописный service worker
(~100 строк): полный контроль и никакой зависимости от сборщика.

## План работ

### 1. Web App Manifest (~30 мин)

- `src/app/manifest.ts` (App Router поддерживает из коробки, генерирует `manifest.webmanifest`):
  `name: 'NRadio'`, `short_name: 'NRadio'`, `start_url: '/'`, `display: 'standalone'`,
  `theme_color: '#202124'` (second-bg-color), `background_color: '#292A2D'` (bg-color), `orientation: 'any'`.
- Иконки: 192×192 и 512×512 PNG (+ вариант `maskable`), `apple-touch-icon` 180×180 для iOS.
  Нарезать из текущего логотипа (оранжевый «play»-круг из шапки).

### 2. Service worker `public/sw.js` (~1–2 ч)

Стратегии кэширования:

| Ресурс | Стратегия |
|---|---|
| Навигация (HTML) | network-first, fallback → кэш `/` (offline app-shell) |
| `_next/static/**` (бандлы), favicon, manifest | cache-first + разовая загрузка в runtime |
| Аудио-потоки (cross-origin, ice*.somafm.com и др.) | **не кэшировать вообще** |

Технические детали:

- версия в имени кэша (`nradio-v1`); в `activate` удалять старые кэши;
- `self.skipWaiting()` + `clients.claim()` — новая версия начинает работать сразу;
- кэшировать только same-origin запросы.

### 3. Регистрация SW (~15 мин)

- клиентский компонент `ServiceWorkerRegistrar`, подключается в `src/app/layout.tsx`:
  `useEffect(() => { navigator.serviceWorker.register('/sw.js') }, [])`;
- регистрировать **только в production** (`process.env.NODE_ENV === 'production'`),
  чтобы не мешать HMR в dev.

### 4. Офлайн-поведение UI (проверка; нового кода — ноль)

Ожидаемый сценарий офлайн-старта установленного приложения:

1. из кэша отдаётся HTML (в нём SSR-разметка + hydrate-данные queryClient со всеми станциями);
2. бандлы отдаются из кэша, React Query гидрируется из HTML;
3. `clientStateMergeMutate` подтягивает лайки/свои станции из `localStorage`;
4. GTM-запросы тихо фейлятся (async), UI не блокируется.

Что сохранится офлайн: список станций, лайки, свои станции, выбранная станция, тема (ColorPicker).
Что не будет работать: аудио-потоки → плеер покажет error; можно заменить технический текст на
дружелюбное «Нет сети, включите интернет» (мелкий тюнинг в `Station.tsx`, ~15 мин).

iOS-нюанс: localStorage обычной вкладки Safari может чиститься после 7 дней неактивности (ITP),
но для установленной на домашний экран PWA хранилище живёт фактически постоянно; после iOS 16.4
установленные PWA поддерживают и service worker, и push.

### 5. Верификация (~30 мин)

- Lighthouse (категория PWA): installable + offline;
- DevTools → Network → Offline → reload: страница и станции открываются, лайки на месте;
- Chrome desktop: кнопка «install» в адресной строке, открывается в отдельном окне без адресной строки;
- Android Chrome → «Установить приложение»; iOS Safari → «На экран “Домой”»;
- после нового деплоя проверить, что старый кэш удаляется и отдаётся свежий HTML.

### 6. Полировка (опционально)

- UX обновлений: SW сообщает о новой версии → тост «Доступна новая версия — обновить»
  (перезагрузка после `controllerchange`);
- fallback-страница offline для непредзагруженных URL;
- Lighthouse ≥ 90 в Performance/PWA стабильно;
- конфиг с коротким `Cache-Control` для `sw.js`, чтобы новые версии подтягивались быстро.

## Итого

| Шаг | Время |
|---|---|
| manifest + иконки | 30 мин |
| service worker + регистрация | 1–2 ч |
| проверка офлайна + установка | 1 ч |
| **минимальный рабочий PWA** | **2–4 ч** |
| полировка (UX обновлений, fallback, сообщения) | +2–4 ч |
