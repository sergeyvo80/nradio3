# Скил «Визуализация плеера» (Winamp-style)

Устройство, отладка и правила развития визуализатора. Компонент:
`src/components/Visualizer/`, движок: `src/api/visualizerEngine.ts`.

## 1. Архитектура

```
клик play (жест пользователя)
        │
        ├─ getVisualizerAudio()   — лениво создаёт «визуализаторный» <audio>
        │                          + AudioContext + AnalyserNode (fftSize 2048)
        ├─ resumeVisualizer()     — заводит контекст (state: running)
        └─ probeCorsStream(url)   — fetch Range: bytes=0-0, кэш по URL (~300мс)
                │
        ┌─ ACAO есть ──────────────► играет «визуализаторный» элемент
        │                             (звук: src → analyser → destination)
        └─ ACAO нет ───────────────► играет обычный `player` (напрямую),
                                      визуализатор рисует псевдо-VU
```

- Поток тянется **параллельно с пробой**: `src` ставится на routed-элемент до `await`
  (повторный play той же станции не пересоздаёт соединение — src сравнивается по
  абсолютному URL).
- `currentPlayer` (NRadioContainer) — какой элемент играет сейчас; pause/switch
  всегда через него. При смене элемента старый ставится на паузу, у routed при
  отказе пробы обрывается загрузка (`removeAttribute('src') + load()`).
- `silentRoutedStreams` — потоки, у которых граф Web Audio молчал: играются
  сразу напрямую, минуя повторную диагностику.

## 2. Рендер (Visualizer.tsx)

- Один `requestAnimationFrame`-цикл; **на паузе цикл останавливается**
  (рисуется статичная полоска, экономия батареи).
- Режимы: `bars`, `wave` (осциллоскоп) и три фуллскрин-режима из
  `modes.ts` — `aurora`, `ridges`, `pulse`. Клик в фуллскрине циклически
  идёт по 10 шагам: для КАЖДОГО режима сначала монохромная версия, затем
  цветная (`STEPS` = mono/color попарно). Компактная панель всегда рисует
  `wave` (при выходе из фуллскрина шаг сбрасывается на wave/mono).
- Цветные версии: `bars` — радуга по полосам (`bandColor`, hue 0→300);
  `wave` — линия-градиент по ширине (5 оттенков cyan→violet);
  `aurora` — слои фиолетовый 275 / циан 190 / зелёный 130;
  `ridges` — гребни по оттенкам от мадженты 300 (старые) к зелени 140 (новые);
  `pulse` — лучи по `bandColor`, ядро синее 205, кольцо маджента 330.
  Монохромные версии unchanged (акцент темы); флаг `colorful` приходит
  в `Spectrum` вместе с `bandColor(i, bands)`.
- bars: логарифмический обход спектра (`pow(i/bands, 1.6)`), градиент
  `--current-color` → `--item-color`, падающие пик-«шапки» (decay 0.008/кадр).
- Новые режимы (`modes.ts`): каждая фабрика — рендерер со своим состоянием
  (сглаженные энергии, история гребней), спектр читается ОДИН раз за кадр
  в Visualizer и передаётся интерфейсом `Spectrum` (`read`, `energy`,
  accent/cap/bg). Псевдо-VU и dead-кадры считаются централизованно.
  - `aurora`: три слоя волн (бас — нижний широкий полупрозрачный,
    середина — средний, верха — яркая кромка 2px), заливка `globalAlpha`
    акцентом вниз до низа; монохром, без свечения.
  - `ridges`: спектр-история стеком (16 строк по 28 полос), сечение раз в
    3 кадра, заливка цветом `--bg-color` перекрывает предыдущие гребни,
    новейший ярче (alpha 0.25→1).
  - `pulse`: радиальный спектр — ядро дышит басом (`energy(0)`, alpha 0.18),
    32 луча со спадом 0.90/кадр, медленное вращение (rot 0.0025/кадр).
- Псевдо-VU: 20 кадров сплошных нулей в аналайзере → плавная имитация
  (`sin`-композиция, басы тяжелее). Включается и при потоках без CORS.
- Цвета читаются из CSS-переменных каждый кадр — смена темы/пикера подхватывается
  без подписок.
- Canvas скейлится под `devicePixelRatio` (кап 2) каждый кадр (`syncSize`).

## 3. Полноэкранный режим

- Нативный `requestFullscreen()`; промис отклонён / API нет (iOS Safari) →
  CSS-оверлей `--overlay` (fixed inset 0 **+ width/height 100%** — без них
  оверлей остаётся компактным 96×40; z-index 1000) — в PWA standalone
  это и есть настоящий фуллскрин.
- Выход: Esc (нативно и по keydown для оверлея) или ✕ (`.close`).
- Состояние `full` синхронизируется событием `fullscreenchange`.
- Смена режимов работает в ОБОИХ вариантах фуллскрина (`full || overlay`) —
  клик по панели в оверлее циклически меняет режим, а не заново открывает
  оверлей.

## 4. Отладка «визуализация есть — звука нет»

Симптомы → причины → действия (все ловили на живом приложении):

| Симптом | Причина | Действие |
|---|---|---|
| Нет звука у части станций | Контекст suspended: создан вне жеста (например, после `await`) | Контекст создаётся **синхронно в клике**, до любого `await` |
| Нет звука у станций без ACAO | Спека: cross-origin поток через MediaElementSource → тишина | Такие станции играют только напрямую, routed не используется |
| Звук стартует через ~25-30 с, визуализация (псевдо-VU) идёт с первого раза | routed-элемент без `crossOrigin`: CORS-медиа считается tainted, MediaElementSource выдаёт нули, страховка ждёт 12 с + второй буферинг на прямом элементе | `crossOrigin='anonymous'` НА ROUTED-ЭЛЕМЕНТЕ (проба уже гарантирует ACAO); на обычном player ставить нельзя |
| Музыка стартует через ~10 с | Watchdog убивал буферизующийся поток (4 с тишины = «мёртвый граф») | Два порога: ctx не running → 2 с; running, но тихо → 12 с |
| Страховка срабатывает у всех | `isAnalyserSilent()` видит нули при буферизации | См. пороги выше; буферизация — не тишина графа |

Инструменты:
- событие **`nr-audio-fallback`** (window) — сработала страховка, звук переключён
  на прямой элемент;
- в консоли: `window.__viz = visualizerContextState` недоступен — состояние
  контекста смотрится через маркер события и `isAnalyserSilent()` (движок
  синглтонный, наружу не экспонируется намеренно).

## 5. Правила и подводные камни (не нарушать)

1. **`crossOrigin` на ОБЫЧНОМ `<audio>` (player) не ставить никогда** — станции без ACAO
   перестанут играть вовсе (медиа-запрос потребует CORS-заголовки). На визуализаторном
   routed-элементе, наоборот, ОБЯЗАТЕЛЕН `crossOrigin='anonymous'`: проба уже проверила
   ACAO, без него CORS-медиа tainted и граф молчит (звук стартует ~через 30 с).
2. `createMediaElementSource` для одного `<audio>` допустим **только один раз** —
   поэтому routed-элемент синглтонный, повторный вызов бросает ошибку.
3. Любой `await` **разрывает контекст жеста пользователя** — создание AudioContext
   и `resume()` должны происходить до первого `await` в обработчике клика.
4. Пробу потока делать `Range: bytes=0-0` + `AbortController` (3 с) +
   `res.body.cancel()` — иначе fetch тянет аудиопоток до конца.
5. Не глушить буферизацию: тишина аналайзера первые секунды на живом потоке —
   это норма (соединение + буфер), а не мёртвый граф.
6. rAF-цикл останавливать на паузе и при скрытой вкладке (пока — достаточно
   остановки на паузе).
7. Звук важнее спектра: любые сомнения — в пользу прямого элемента
   (визуализация деградирует в псевдо-VU, звук не теряется).

## 6. Как расширять

- **WebGL-пресеты** (fire/plasma/particles): 2D-пресеты уже есть в
  `modes.ts` (aurora/ridges/pulse); WebGL-варианты — та же схема: фабрика
  рендерера, интерфейс `Spectrum`, тот же аналайзер и watchdog.
- **Серверный CORS-прокси** (`/api/stream?url=`) — НЕ делать без нужды: весь
  трафик пойдёт через Vercel Functions; псевдо-VU дешевле и надёжнее.
- Новые режимы добавлять в массив `MODES` в Visualizer.tsx (цикл кликов
  фуллскрина) и фабрику в `modes.ts`; компактная панель всегда рисует `wave`.
